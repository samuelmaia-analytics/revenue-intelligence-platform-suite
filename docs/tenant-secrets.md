# Tenant Secrets

## Why This Exists
This platform now supports a production-minded secret resolution layer by tenant and environment. The goal is to preserve the reusable white-label architecture without ever storing live credentials in versioned client configuration.

## Resolution Order
Secrets are resolved in a strict override order:
1. `config/secrets/global.json`
2. `config/secrets/environments/<deployment_env>.json`
3. `config/secrets/clients/<client_profile>.json`
4. `config/secrets/tenants/<deployment_env>/<client_profile>.json`
5. environment variables in the form `TENANT_SECRET__SECTION__KEY`

This lets the same platform support shared defaults, environment-specific runtime secrets, client-level connectors, and isolated tenant overrides.

## What Is Committed
Only templates are committed:
- `config/secrets/templates/global.template.json`
- `config/secrets/templates/environments/*.template.json`
- `config/secrets/templates/clients/*.template.json`

These templates define the required shape for:
- CRM credentials
- storage and signed-link behavior
- observability webhooks
- runtime signing and cookie secrets
- client-specific connector credentials

## What Stays Private
The following paths are intentionally ignored by Git:
- `config/secrets/global.json`
- `config/secrets/environments/*.json`
- `config/secrets/clients/*.json`
- `config/secrets/tenants/**/*.json`

This separation is important for LGPD, tenant isolation, and commercial operation with multiple live clients.

## Validation And Runtime
The platform includes:
- `packages/common/secrets.py` for secret template loading, secret loading, and masked readiness checks
- `scripts/check_tenant_secrets.py` for operator validation
- `reports/showcase/tenant_secret_status.json` generated by the showcase
- `/profiles/{profile_id}/secret-status` in the executive API

The readiness output is masked by design. It reports completeness and source layer, but never secret values.

## Commands
```bash
make tenant-secrets-check
CLIENT_PROFILE=healthtech_growth DEPLOYMENT_ENV=production make tenant-secrets-check
REQUIRE_TENANT_SECRETS=1 CLIENT_PROFILE=saas_b2b DEPLOYMENT_ENV=production python scripts/check_tenant_secrets.py
```

## Recommended Operating Policy
- Keep real tenant secrets outside Git, even in private repositories
- Use environment-variable overrides in hosted environments when possible
- Treat `production` as strict, with mandatory readiness checks before release or client go-live
- Expose only masked completeness status to dashboards and APIs
