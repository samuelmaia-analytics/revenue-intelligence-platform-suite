# Privacy And LGPD Policy

## Purpose
Define the minimum privacy and LGPD-oriented controls expected for analytics, decision-support, and client-facing assets in this repository.

## Scope
This policy applies to:
- showcase datasets and generated artifacts
- client adaptation profiles
- executive insight outputs
- proposal, deal-room, and go-to-market assets

## LGPD Control Principles
- purpose limitation: only process data required for a defined business outcome
- adequacy: metrics and features must align with the stated use case
- necessity: minimize personal and sensitive data in all repository flows
- transparency: document how decision-support outputs are generated
- security: restrict sensitive data exposure and use anonymized samples in-repo
- prevention: use contracts, scorecards, and gates to block unsafe promotion
- accountability: record ownership, review cadence, and remediation path

## Repository Rules
- no raw personal data or direct identifiers should be committed
- all sample data must be anonymized, synthetic, or demonstrably sanitized
- executive outputs must avoid exposing personal data unless explicitly authorized
- deal rooms, proposal packs, and GTM exports should carry business context, not sensitive raw records

## Required Controls
- source owner and legal basis registered before operational onboarding
- retention policy documented for each client dataset
- sensitive field review before feature engineering or semantic publication
- re-identification risk review before sharing artifacts externally
- approval path for any exception involving personal or sensitive data

## Review Cadence
- weekly: freshness, quality, and contract review
- monthly: privacy, retention, and access control review
- quarterly: full governance review aligned to release evidence
